# 権限について

## マップの公開範囲

- **公開**はTOPページの「公開マップ」一覧に掲載され、共有キーなしで誰でも閲覧できます。「公開マップ」の入口はフォルダ・マップと同じカード一覧の先頭に固定します。公開一覧には名前検索、作成日・更新日・タイトルの昇順／降順を用意します。
- **URL限定公開**は一覧に掲載されず、「共有URLをコピー」で取得した共有キー付きの URL からログインせずに開けます。そのリンクで閲覧できるのは、対象マップとそのピン・コメント・画像です。
- **非公開**は、作成者と管理者が開けます。他の人が URL を直接開くと「マップが見つかりません」と表示されます。
- 非公開マップにはURLをコピーする操作を表示しません。公開・URL限定公開マップだけに「共有URLをコピー」を表示します。
- 作成者と管理者は共有キーなしでも開けます。ログイン済みの一般ユーザーが正しい共有リンクを開くと、そのユーザーに対象マップの閲覧権限を記録します。その後は保存済み一覧や共有フォルダからも開けます。フォルダの URL だけで、中のマップの閲覧権限が追加されることはありません。
- 新規作成時はプルダウンで公開範囲を選び、初期値は「公開」です。従来の画面で「公開」だった既存マップは、すべて「URL限定公開」に移行します。既存マップが自動で公開一覧に載ることはありません。
- 作成者と管理者は3種類の公開範囲を変更できます。公開はマップ単位で、元の所属フォルダや同じフォルダの他マップは公開しません。
- 公開範囲を変更すると共有キーを更新し、記録済みの受信者の権限も解除します。公開からURL限定公開に変わった場合は、保存済みでも保存を根拠には開けず、新しい共有URLを受け取る必要があります。非公開に変わった場合は、共有URLがあっても作成者と管理者以外は開けません。
- 再びURL限定公開にした場合も古い共有URLは使えません。必要な相手に新しいURLを渡してください。共有キーはリンクを知っている人が使えるため、共有先を広げたくない場合は URL を第三者に渡さないでください。
- 開いている画面も約10秒ごと、またはウィンドウに戻ったときに閲覧権限を再確認します。すでに閲覧・取得された内容を相手の手元から消すことはできません。

## 自分のマップ一覧への保存と保存解除

- 閲覧可能な他人のマップを「自分のマップ一覧に保存」すると、元の所属フォルダに関係なくTOPページに直接表示されます。保存にはログインが必要です。
- 保存後は押せる「保存解除」ボタンになります。解除するとTOPページの保存による表示と、マップ移動ボタン作成時の候補から外れます。元マップや既存の移動ボタンは削除しません。自分で作ったマップは保存解除の対象外です。
- マップ一覧ではカードの三点メニュー内から「保存解除」を選びます。マップ詳細では「保存解除」ボタンを表示します。
- 保存は元マップへの参照です。複製や所有者の変更は行わず、元マップの更新が表示されます。保存・解除の状態は再ログイン後も保持されます。
- 保存は閲覧・編集・管理の権限を追加しません。保存後に公開範囲が変わった場合も最新の条件に従い、閲覧できないマップはTOPの一覧や移動先候補には表示しません。

## ユーザーごとにできること

表の「自分のマップ」「自分のピン」は、それぞれ自分が作成したものを指します。

| 利用者 | 公開マップ | URL限定公開マップ | 非公開マップ |
| --- | --- | --- | --- |
| ログインしていない人 | マップ・ピン・コメントを閲覧できる。 | 共有キー付き URL の対象マップとピン・コメントを閲覧できる。 | 閲覧できない。 |
| ログイン済みの一般ユーザー | 閲覧でき、ピン・コメントを投稿できる。 | 自分のマップと、共有リンクを受け取ったマップを閲覧し、ピン・コメントを投稿できる。 | 自分のマップだけ閲覧・投稿できる。 |
| 管理者 | すべてのマップ・ピン・コメントを閲覧・投稿・管理できる。 | すべて閲覧・投稿・管理できる。 | すべて閲覧・投稿・管理できる。 |

- マップの編集では、タイトル・説明・公開範囲を変更できます。管理者がマップやピンを編集しても、元の作成者は保持されます。
- 閲覧できるログインユーザー全員が、保存の有無に関係なくピンとコメントを投稿できます。未ログインユーザーは保存・投稿できません。閲覧権限を失った後の投稿はデータベース側でも拒否します。
- マップの編集・削除は作成者と管理者だけ、ピン・コメントの編集・削除はその投稿者本人と管理者だけができます。
- 管理者はヘッダーの「マップ管理」から3種類すべてのマップを開けます。マップは詳細画面のメニュー、ピンはピンを開いたパネルから編集・削除できます。
- マップ移動ボタン作成時の候補は、自分が作成したマップと自分の一覧に保存したマップのうち、現在閲覧できる公開・URL限定公開マップだけです。非公開マップは作成者・管理者にも候補として表示しません。公開されているだけ、共有URLを開いただけ、フォルダを保存しただけのマップは追加しません。
- 既存のマップ移動ボタンは、押した人が移動先を閲覧できれば利用できます。保存解除後もリンクは残りますが、移動の直前に改めて閲覧権限を確認します。
- めもっぷにアップロードしたマップ画像も、マップと同じ閲覧権限で表示されます。
- 未ログインの共有画面は、表示中に約10秒ごと、またはウィンドウに戻ったときにピンとコメントを取得し直します。取得時には共有キーを提示し、閲覧できるデータだけを受け取ります。

## 公開マップ機能の適用手順（Issue #29）

1. 次のIssue #10の準備用SQLを適用し、共有キー・受信者・閲覧ルールを用意します。
2. [公開範囲の移行SQL](../supabase/migrations/20261124085317_public_map_visibility.sql) を実行します。既存の `is_public=true` はすべてURL限定公開、`false` は非公開に移行します。移行するだけでは共有キーを変更しません。
3. Issue #29の新しいフロントエンドを公開し、公開一覧・保存解除・作成時の公開範囲・投稿を確認します。
4. Issue #10の切り替え用SQLが未適用なら、公開に合わせて適用します。共有ヘッダーを省略した直接リクエストにも限定公開の制限を適用するために必要です。

旧フロントエンドからの作成・公開設定変更は従来のURL限定公開／非公開として扱います。新規作成時の「公開」の初期値は、新しいUIが明示的に指定します。公開範囲を変更した後に古い共有キー・受信記録を無効にする点は、Issue #10単体の挙動から変更されています。

本番反映前に `npm test` で権限のテストを実行できます。テストはローカルのPostgres互換環境と架空のユーザー・マップを使い、本番DBには接続しません。

## URL限定公開の切り替え手順（Issue #10）

本番アプリの公開と DB 設定を、次の順番で切り替えます。RLS は「誰がどのデータを読んだり更新したりできるかを、データベース側で決める仕組み」です。

1. [準備用 SQL](sql/20261124082657_map_share_scope_prepare.sql) の全体を実行します。API から直接読めない領域にマップ別の共有キーと受信者の記録を追加し、閲覧条件と共有用関数を用意します。この段階では新しいアプリのリクエストだけが新しい閲覧条件を使い、旧アプリのリクエストは従来のまま動きます。
2. 新しいコードをローカルで確認します。所有者が「共有URLをコピー」で取得した A のリンクを別ブラウザで開き、A のみ閲覧できること、B に移動できないこと、B 自身のリンクなら開けることを確認します。所有者と管理者の操作も確認します。
3. 新しいコードを本番へ公開し、所有者が共有キー付き URL をコピーできることを確認します。従来の共有 URL にはキーがないため、必要な相手には新しい URL を渡し直します。
4. 本番公開に合わせて、[切り替え用 SQL](sql/20261124082659_map_share_scope_enable.sql) の全体を実行します。以降は旧アプリや直接の API リクエストにも新しい閲覧条件を適用します。手順1だけでは、直接リクエストから別の公開マップを取得することは防げません。
5. ログアウトした別ブラウザで共有キーなしの旧 URL が開けないことと、新しいリンクで対象のマップ・ピン・コメント・画像だけを閲覧できることを確認します。

確認用データはローカルのテスト環境で用意し、本番 DB や PR には追加しません。Supabase の `map-images` バケットは非公開に保ち、Storage の閲覧ルールも有効にしておきます。公開バケットでは画像の閲覧条件を適用できません。

Supabase の診断画面では、`private.map_share_*` の3テーブルに [RLS のポリシーがないという通知](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) が出ます。直接の読み書きを全員に拒否するための設定です。また、共有用の2関数には [SECURITY DEFINER の通知](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable) が出ます。これは関数内だけで DB 所有者の権限を使う仕組みで、API から読めない共有記録を操作するために使っています。実行はログイン済みユーザーに限定し、関数内でも所有者・管理者・正しい共有キーの条件を確認します。

## ユーザー管理

- 管理者はヘッダーの「ユーザー管理」から、登録ユーザーと現在の権限を確認し、管理者権限を付与・解除できます。最後の管理者の権限は解除できません。
- 一覧には Supabase Auth の GitHub 連携情報に保存されたユーザー名と、メールアドレス、ユーザー ID が表示されます。ログイン名の情報がない場合は「GitHub ユーザー名なし」と表示されます。
- フォルダ管理・マップ管理の作成者名や、コメント管理の投稿者名を押すと、ユーザー管理の該当ページが開き、そのユーザーの行を強調します。作成者名には GitHub ユーザー名を使い、取得できない場合はユーザー ID を表示します。
- 一覧の取得と権限の変更は、Supabase 側でも操作した人が管理者か確認します。変更されたユーザーの画面は、ページを再読み込みするか、別のタブから戻ると権限を確認し直します。
- この機能を有効にするには、既存の `is_map_admin()` がある Supabase プロジェクトの SQL Editor で、[ユーザー管理用の SQL](sql/issue-11-admin-users.sql)、[GitHub ユーザー名を追加する SQL](sql/issue-11-admin-github-usernames.sql) の順に、それぞれファイル全体を実行します。ユーザー管理用の SQL を適用済みの場合は、GitHub ユーザー名を追加する SQL を実行します。

## フォルダ管理

- 管理者は「フォルダ管理」から全ユーザーのフォルダを開き、フォルダ画面で名前変更・削除できます。名前変更後も作成者と中身は保持されます。
- 削除前に確認を表示します。中のマップと直下の子フォルダは、削除対象の親フォルダへ移動します。親がない場合はホームへ移動し、各マップ・子フォルダの作成者は保持されます。
- 一般ユーザーは自分のフォルダを名前変更・削除できます。従来の持ち主なしフォルダはログイン済みユーザーが削除できます。ほかのユーザーのフォルダ操作は Supabase 側でも拒否します。
- [フォルダ管理用 SQL](sql/issue-12-admin-folders.sql) の全体を SQL Editor で実行すると、一覧・名前変更・削除・作成者名の取得の関数と実行権限を追加します。実行はユーザーデータの削除や移動を行いません。

## コメント管理

- 管理者はヘッダーの「コメント管理」から、公開・URL限定公開・非公開マップのピンに付いたコメントを新しい順に確認できます。マップ名とピン名のリンクを開くと、投稿先のピンと対象コメントが表示されます。
- コメントの投稿者名を選ぶと、ユーザー管理で該当する行が強調されます。メールアドレスはその行で確認できます。
- 管理者はコメント管理の一覧とピンの詳細パネルから、すべてのユーザーのコメントを編集・削除できます。管理用一覧の取得と他のユーザーのコメントの編集・削除は、Supabase 側でも管理者に限定します。編集時は本文だけが変わり、元の投稿者と投稿日時は保持されます。
- 有効にするには、既存の `is_map_admin()` がある Supabase プロジェクトの SQL Editor で、[コメント管理用の SQL](sql/issue-13-admin-comments.sql)、[コメント削除用の SQL](sql/issue-13-admin-delete-comment.sql) の順に、それぞれのファイル全体を実行します。一覧を適用済みの場合は、コメント削除用の SQL を実行します。
- 編集を有効にするには、[コメント編集用の SQL](sql/issue-2-edit-pin-comment.sql) の全体を実行します。
- 投稿者名からユーザー管理の該当ページへ移動できるようにするには、ユーザー管理用の SQL を適用したあと、[投稿者リンク用の SQL](sql/issue-13-admin-comment-author-link.sql) の全体を実行します。
